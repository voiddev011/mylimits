Privacy notice for the MyLimits extension.

Updated 24 October 2026 · Reviewed against version 3.4.0

Default browser tracking needs no MyLimits account or server. MyLimits has no analytics, tracking or advertising. With optional sync off, none of your readings, history, nicknames, settings or credentials is sent to MyLimits or an unrelated third party. The extension does communicate directly with enabled AI providers to request your session and usage information.

What is read

After you enable a provider, selected account, session and usage interfaces may supply account identity, plan, workspace and quota information. Account identities are replaced with salted SHA-256 identifiers before extension account storage. Workspace routing IDs are retained privately; a display name may include the workspace name. Email is not the default nickname.

Gemini and optional Grok / Perplexity activity-only mode observe the URL, method and success status of a small allowlist of existing requests. They do not read request bodies, response bodies, prompt text or chat history. Local activity counts are not account-wide quotas. MyLimits does not send model prompts or inference requests to measure usage.

What stays locally

  • Readings and account state: normalized usage, plan, pseudonymous account IDs, workspace choices, connection state, refresh timestamps and last-known snapshots.
  • History: historical usage readings in IndexedDB. Retention is selectable at 30 or 90 days and pruned on new readings and when you save that setting.
  • Nicknames and settings: names you enter, display and privacy preferences, notification choices, quiet hours, snooze, recovery choices and local widget preferences.
  • Supporting records: local migration recovery copies, bounded notification / observation deduplication records, recovery budgets and temporary tab ownership records, and sanitized diagnostics. These contain no provider credential values.

These ordinary records use browser local storage and IndexedDB. They are not encrypted by MyLimits and do not use browser storage sync. Privacy mode masks the interface and pauses history display / exports; it does not encrypt stored data or stop previously enabled snapshot sync.

Tokens, encrypted credentials and saved sign-ins

Normal website login cookies remain managed by your browser and the provider. Where a usage endpoint needs a ChatGPT bearer token, the extension reads it transiently, uses it only for that provider, and does not persist it, log it, export it or show it in the UI.

Saved sign-ins are disabled for every production provider in the current code. The gated implementation supports explicit per-account consent to save allowlisted session cookies in a separate AES-GCM encrypted local vault. Its non-extractable key lives in IndexedDB; credential ciphertext is kept out of ordinary account state, exports and sync. This is not a currently enabled feature, and the implementation does not save a ChatGPT access token. Encryption cannot protect against malware running as you or someone copying the whole browser profile.

If you explicitly connect optional snapshot sync in a configured build, its MyLimits device token and pairing secret are kept in separate private local storage. That storage is not an encrypted vault. These are app authorization secrets, not provider tokens, and are excluded from normal account state and exports.

Network requests and optional features

Default: the extension’s own requests go only to the enabled providers’ selected session and usage interfaces. It does not forward your data to MyLimits or an unrelated third party. The provider receives requests needed to read its own account data.

Optional snapshot sync: off by default and unavailable without a configured service origin. Connecting requires explicit server access and device approval. It sends normalized account names, plans, pseudonymous source/account/workspace IDs, readings and timestamps to that fixed approved server. Preference sync is a separate choice. No provider cookies, tokens, prompts, conversations or vault ciphertext are uploaded. The default release workflow configures no sync server.

Optional Desktop helper: a separately installed local service uses official Codex / Claude Code profiles and their official authorization flows. Credentials remain in local CLI / OS credential storage, which is not uniformly encrypted. The official tools make authenticated provider requests. Native Messaging carries normalized readings and account metadata, not provider tokens or raw responses. Protected Desktop connection metadata may retain an email for confirmation recovery; the extension’s account storage and exports do not. Desktop browser profiles can contain browser-owned cookies. Its installer downloads selected runtimes from official distribution sources.

Hosted provider collection is not enabled in the default preview. A future deployed hosted collector would require separate disclosure and provider consent; it must not be described as browser-local. This static website has no analytics, cookies, remote fonts or third-party scripts. GitHub serves it through GitHub Pages and handles normal hosting requests under GitHub’s privacy statement. Following release, store or issue links opens that service.

Optional background-tab recovery

With automatic recovery enabled, an eligible failed website check may open one inactive normal provider tab using your existing login. It is limited to eight attempts per provider per day with a 30-minute cooldown. It does not use private / incognito tabs or sign into another account. It closes only its owned inactive tab; if you activate it, it is left open. Turn automatic recovery off in Settings to prevent this behavior. Interactive challenges still need your action.

How to delete your data

  • Forget account: removes its local saved readings, nickname, history and matching migration recovery data. If it is the current tracked website account, that tracking is disabled. A disabled opaque source marker may remain to reject late messages. A saved-sign-in slot, if present, is also deleted.
  • Clear history: removes history while keeping account settings; new readings can still be collected.
  • Uninstall the extension: removes its browser-owned local storage and IndexedDB. It does not sign you out of provider websites.
  • If you enabled sync: delete synced account / all-account data in the sync dashboard. Local forgetting queues remote deletion; offline deletion remains pending until connection succeeds. Uninstalling or clearing local history alone does not remove server copies. Opaque replay-prevention tombstones may remain after server deletion.
  • If you installed Desktop: disconnect accounts in its connection settings to request official CLI logout, and use the helper’s uninstall / local-profile deletion options. Extension uninstall does not remove Desktop credentials. File deletion alone does not prove provider-side revocation; use provider security controls where needed.
